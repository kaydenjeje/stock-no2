# 초보자 구독형 주식 지표 스크리닝 앱 (스캐폴딩)

`docs/product-plan-v1.md`(§3, §8)와 `docs/wireframe-v1.html`을 기준으로 만든 실행 가능한 초기 스캐폴딩입니다.
`stock-no1`은 참고만 했고 수정하지 않았습니다.

## 실행 방법

```bash
python -m venv .venv
source .venv/bin/activate   # Windows는 .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

브라우저가 자동으로 열리지 않으면 터미널에 출력된 주소(기본 `http://localhost:8501`)로 접속하세요.

### AI 지표 해설을 실제로 써보려면 (선택)

`.streamlit/secrets.toml` 파일을 만들고 아래처럼 키를 넣으면 DeepSeek API로 지표 해설을 생성합니다.
키가 없어도 앱은 정상 동작하며, 이 경우 규칙 기반 문구로 자동 대체됩니다.

```toml
DEEPSEEK_API_KEY = "sk-..."
```

## 지금 범위 (MVP)와 의도적으로 뺀 것

- **시장**: 한국(KRX)만 지원합니다. 미국 시장은 §6 다음 단계 항목입니다.
- **스크리닝 대상**: 전종목이 아니라 `lib/data.py`의 `CURATED_KR`(시가총액 상위권 약 40종목)로 한정했습니다. 매 요청마다 전종목을 스캔하면 느려서, 우선 빠르게 돌아가는 걸 우선했습니다. 전종목 확장은 `stock-no1/collect_data.py`처럼 배치 스크립트로 분리하는 걸 추천합니다.
- **매수가 / 목표가 / 손절가는 어디에도 없습니다.** 이는 실수가 아니라 §4·§8 법적 리스크 논의에 따른 의도적 설계입니다.
- **개인 맞춤 챗봇은 없습니다.** §3-2에서 결정한 "A안(챗봇 제거)"을 채택했습니다. 대신 종목 상세의 "AI 지표 해설"은 감지된 지표를 사실대로 설명하는 단발성 생성만 제공합니다.
- **로그인/결제는 목업입니다.** `data/user_state.json` 파일 하나에 단일 게스트 사용자 상태(관심종목, 저널, 구독 상태)만 저장합니다. 실제 다중 사용자 인증과 결제(PG) 연동은 별도 작업이 필요합니다.
- **알림은 푸시/이메일로 발송되지 않습니다.** 관심종목 화면에 들어갈 때마다 그 시점 지표를 계산해서 피드처럼 보여주는 방식입니다. 실시간 발송은 §8-3 D의 다음 단계입니다.

## 다음으로 할 만한 것

1. 전종목 스크리닝 배치화 (캐시된 JSON을 앱이 읽는 구조로 `collect_data.py` 패턴 재사용)
2. 실제 로그인 (이메일/소셜) + 사용자별 상태 저장(DB)

4. 알림 발송 (이메일 또는 웹푸시)
5. 문구 최종본에 대한 변호사 검토 (§5)
